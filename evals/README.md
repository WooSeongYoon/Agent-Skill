# 스킬 평가

## 구조 검사와 행동 평가 구분

`python scripts/validate.py`는 스킬 metadata와 참조, profile, native agent 어댑터, 평가 데이터의 형식을 검사합니다. `python -m unittest discover -s tests -v`는 설치 도구의 파일 처리와 충돌 보호를 검증합니다. 이 결과는 모델이 스킬을 적절히 선택한다는 증거가 아닙니다.

[cases.json](cases.json)은 14개 평가 요청, 기대 스킬, 제외 스킬, 판단 기준을 담습니다. 일부는 스킬이 발동하지 않아야 하는 부정 사례입니다. 기대 목록은 유일하게 허용되는 답변 경로가 아니라 해당 요청의 핵심 관련 스킬 기준입니다. 예를 들어 완료 단계의 verify-change나 최초 조사용 project-discovery는 작업 맥락에 따라 추가될 수 있습니다.

## 실행 절차

1. 실제 사용할 Codex 또는 Claude 버전과 모델, 설치 프로필을 기록합니다.
2. 각 요청을 독립 세션에서 실행합니다. 암묵적 선택을 평가할 때 기대 스킬과 정답 기준을 모델에 보여주지 않습니다.
3. 명시적 사용 평가에서는 사용할 스킬과 원본 코드만 제공합니다. 진단 결과나 의도한 수정은 미리 알려주지 않습니다.
4. 선택된 스킬, 근거 파일, 실행 명령과 결과, 변경 diff를 보관합니다.
5. 요청 범위 준수, 사실/추측 구분, 검증 품질, 불필요한 도구 실행, 기술적 정확성을 각각 검토합니다.
6. 실패를 고친 뒤 같은 사례와 다른 유사 사례를 다시 평가합니다. 평가지표를 임의의 성공률로 포장하지 않습니다.

## 이번 작성 시 확인한 범위

2026-11-02, 각각의 스킬과 코드만 전달한 별도 에이전트 세션에서 Qt와 ML 진단을 관찰했습니다. 의도한 답이나 수정 방향은 전달하지 않았습니다. 파일 수정·GUI·학습·외부 서비스 실행은 요청하지 않았습니다.

| 사례 | 관측한 진단 | 지켜진 경계 |
|---|---|---|
| Qt | blocking worker의 queued cancel 지연, worker의 QLabel 직접 수정, GUI의 wait() 정지, 종료·정리 연결 누락, 중복 시작과 시작 전 닫기 문제를 코드 위치와 연결 | 현재 QObject 구조를 유지하는 수정 방향을 제시했고 실제 GUI 실행은 미검증으로 표시 |
| ML | 분할 전 scaler fit, 테스트 데이터로 checkpoint 선택, no_grad와 eval의 차이, 전처리 복원 경로 누락을 지적 | 호출 전 모드와 test_loader의 실제 의미는 미확인으로 남겼고 학습·GPU를 실행하지 않음 |

두 사례 모두 해당 스킬의 핵심 판단이 나타났지만 **명시적 스킬 사용에 대한 정적 진단 2건**입니다. 전체 14개 요청의 암묵적 선택 정확도, Codex/Claude의 실제 로더 호환성, GPU/GUI 동작의 통과를 뜻하지 않습니다. 제품별 모델·버전 비교 점수나 통계적 성능 향상 수치는 측정하지 않았습니다.

사용자 프로젝트의 최종 수용 테스트는 [적용 절차](../docs/project-adoption.md)에 따라 별도로 수행합니다.

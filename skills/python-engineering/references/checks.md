# Python 점검

- I/O 경계에서 파일 인코딩, 빈 입력, 누락된 파일, 잘못된 타입을 확인한다. 내부 불변 조건까지 불필요하게 방어하지 않는다.
- subprocess는 argv 리스트와 명시적 cwd를 사용한다. 사용자 입력을 shell=True 문자열에 넣지 않는다.
- 파일·소켓은 context manager로 정리한다. 시간, 난수, 네트워크는 테스트가 필요한 경계에서만 분리한다.
- async 함수에서 blocking I/O를 실행하지 않는다. 스레드/프로세스 선택은 I/O, GIL, 공유 상태와 취소 요구를 근거로 한다.
- 새 의존성이 필요하면 기존 기능으로 해결 가능한지와 지원 버전·라이선스를 확인한다. 버전 숫자를 추정하지 않는다.
- 테스트는 실제 실패와 계약을 검사한다. private 함수 호출 횟수나 구현 복사로 검증을 대체하지 않는다.
- 확인한 설정이 있을 때만 `python -m pytest`, `ruff check`, `mypy` 같은 명령을 선택한다. 도구가 없다는 이유로 프로젝트 도구 체인을 통째로 바꾸지 않는다.

[Python 공식 문서](https://docs.python.org/3/)에서 사용 중인 Python 버전의 API를 확인한다.

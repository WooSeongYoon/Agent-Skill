# Python 구현

1. pyproject.toml, 잠금 파일, CI와 대상 모듈의 호출자를 읽고 지원 버전과 공개 계약을 확인한다.
2. 입력·출력·실패 조건과 최소 수정 범위를 정한다. 버그는 기존 증상을 재현하고 가능하면 먼저 회귀 테스트로 고정한다.
3. 함수, dataclass, 단순한 클래스와 합성으로 구현한다. 단일 사용을 위한 추상화, 다중 상속, 불필요한 프레임워크를 추가하지 않는다.
4. `hasattr`, `getattr`, `setattr` 대신 명시적인 속성과 데이터 구조를 쓴다. 외부 API 때문에 필요하면 이유와 적용 범위를 설명한다.
5. f-string과 join을 우선한다. 반복 문자열은 리스트에 모은다. 예외를 좁게 잡고 원인과 필요한 문맥을 보존한다.
6. 프로젝트가 이미 사용하는 포맷·린트·타입 검사·테스트 명령을 실행한다. 테스트 도구가 없으면 표준 라이브러리 unittest 또는 작은 실행 검증 등 요구에 맞는 최소 수단을 선택한다.
7. 관련 테스트 뒤에 영향 범위가 요구하는 빌드/전체 검증을 수행한다. 환경 문제와 코드 실패를 나누어 보고한다.

경계 조건은 [Python 점검](references/checks.md)을 필요한 부분만 읽는다.

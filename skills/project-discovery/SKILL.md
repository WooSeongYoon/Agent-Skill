# 프로젝트 파악

1. 요청을 한 문장으로 정리하고 변경할 동작과 확인 방법을 연결한다.
2. 현재 경로와 Git 상태, 루트 및 대상 경로의 지침을 확인한다. 사용자 변경은 보존한다.
3. README, pyproject.toml, 잠금 파일, package.json, Dockerfile, Compose, CI 중 존재하는 파일만 읽는다. 비밀 설정과 대용량 데이터는 열거하거나 출력하지 않는다.
4. Python 버전, Qt 바인딩, 웹/ML 프레임워크, 패키지 관리자, CPU/GPU 조건을 증거 파일과 연결한다. 확인되지 않은 값은 미확인으로 남긴다.
5. 기존 CI와 프로젝트 설정에서 setup/lint/typecheck/test/build/smoke 명령을 찾는다. 작업 디렉터리, 필요한 서비스와 부작용도 확인한다.
6. `.harness/project.json`이 있으면 확인한 사실과 명령을 기록한다. 명령은 셸 문자열 대신 argv 배열로 저장한다. 문서의 예시를 검증된 명령으로 기록하지 않는다.
7. 관련 분야 스킬만 선택한다. 구현 전에 요구사항, 가정, 성공 기준, 최소 변경 계획을 제시한다.

기록 항목과 복합 프로젝트의 경계는 [프로젝트 지도](references/project-map.md)를 따른다.

## 결과

확인된 기술 스택과 근거 경로, 수정 범위, 실행 가능한 검증, 필요한 추가 정보를 보고한다. 명령 확인과 테스트 통과를 구분한다.

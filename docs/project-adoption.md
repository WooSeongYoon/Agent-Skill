# 실제 프로젝트 적용 절차

## 1. 프로필 선택

| 프로젝트 | 권장 선택 |
|---|---|
| Python 라이브러리/CLI | python |
| PySide/PyQt 데스크톱 | qt |
| Qt + 모델 추론 + 컨테이너 | qt ml docker |
| Python API + 웹 프론트엔드 | python web |
| 웹 + API + 컨테이너 | python web docker |
| 모델 학습/평가 | ml |

이 선택은 지침 설치 범위입니다. 라이브러리나 런타임을 설치하지 않습니다.

## 2. 기존 규칙과 합치기

작업 브랜치에서 시작하고 원래 Git 변경을 확인합니다. 설치기를 미리보기로 실행합니다. 기존 지침이 있으면 `--skip-instructions`를 사용하고 `.harness/instructions.md`를 검토하여 기존 규칙에 수동 통합합니다. 회사/프로젝트의 더 구체적인 규칙을 제거하지 않습니다.

파일 충돌을 자동 해결하지 않습니다. 새 버전을 빈 디렉터리에 생성한 후 비교합니다. `.harness/installed.json`의 hash는 최초 설치 상태 기록이며 사용자의 편집을 금지하거나 자동 복구하는 기능이 아닙니다.

## 3. 프로젝트 사실 채우기

`.harness/project.json`의 null은 의도적인 미확인 값입니다. 프로젝트에서 실제로 확인한 값만 입력합니다.

- Python 지원 버전과 실제 CI 실행 버전
- Qt 바인딩/버전, Widgets/QML, 지원 OS
- 웹 프레임워크, 패키지 관리자와 lockfile
- ML 프레임워크, CPU/GPU, 드라이버·CUDA 조건
- 실제 setup/lint/typecheck/test/build/smoke 명령

명령 값은 argv 배열입니다. 작업 디렉터리, 서비스, 환경 조건은 notes에 기록합니다. 설치기는 명령을 자동 실행하지 않습니다. 사용자가 숨겨 둔 시크릿이나 원본 데이터의 내용을 이 파일에 기록하지 않습니다.

## 4. 대표 작업 한 개로 확인

처음부터 큰 기능을 맡기지 말고 기존 버그 또는 작은 동작 변경 하나를 선택합니다.

- Qt: 시작 → 진행 → 취소 → 재실행 → 창 닫기.
- 웹: 정상 제출 → 잘못된 입력 → API 실패 → 재시도.
- ML: 작은 배치의 shape/loss → train step → 추론 → checkpoint 재로드.
- Docker: config 검사 → build → 임시 실행 → 준비 상태 → 정상 종료.

에이전트가 읽은 스킬, 변경 diff, 실제 명령/종료 코드, 실행하지 못한 범위를 기록합니다. 이 검증을 통과한 뒤 범위를 넓힙니다.

## 5. 여러 프로젝트 운영

공통 원칙은 Agent-Skill 원본에서 유지하고 실제 명령·디렉터리·도메인 계약은 각 프로젝트에 둡니다. 여러 프로젝트의 서로 다른 Python·CUDA 버전을 하나의 전역 규칙에 섞지 않습니다. 글로벌 설치나 전역 config 자동 변경을 하지 않는 이유입니다.

# 웹 구현

1. package.json, lockfile, 라우팅, API 계약, 스타일 체계, 기존 테스트를 확인한다. 새 프레임워크나 디자인 시스템을 임의로 추가하지 않는다.
2. 변경할 사용자 흐름과 성공·빈 데이터·로딩·오류 상태를 정한다. API의 입력 검증과 클라이언트 표시를 분리한다.
3. 의미 있는 HTML, label, 키보드 조작, 초점 이동, 반응형 레이아웃을 구현한다. 색만으로 상태를 구분하지 않는다.
4. 클라이언트에 시크릿을 넣지 않는다. 외부 HTML과 입력은 사용하는 프레임워크의 검증/이스케이프 방식을 따른다. 인증·권한은 서버에서 검증한다.
5. 기존 린트·타입 검사·테스트·빌드를 실행한다. 브라우저가 있으면 변경한 사용자 흐름과 작은/큰 화면을 검증한다.
6. Playwright에서는 role/label 등 안정적인 locator와 사용자에게 보이는 상태 assertion을 우선한다. networkidle이나 고정 sleep을 보편적인 준비 완료 조건으로 쓰지 않는다.
7. 브라우저 콘솔과 요청 실패를 확인하고 필요한 화면 증거를 남긴다. 빌드 성공을 브라우저 검증 완료로 보고하지 않는다.

브라우저 범위는 [웹 검증](references/browser-checks.md)을 따른다.

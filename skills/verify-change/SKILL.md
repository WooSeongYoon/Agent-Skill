# 변경 검증

1. 원래 요청과 diff를 대조한다. 범위 밖 변경, 비밀 값, 임시 산출물과 사용자의 기존 변경이 섞이지 않았는지 확인한다.
2. 성공 기준마다 이를 입증할 검사와 환경을 정한다. 프로젝트의 기존 검증 명령을 우선한다.
3. 변경한 동작에 맞는 테스트 또는 빌드를 실제 실행한다. 버그는 원래 재현 경로를 다시 확인한다.
4. 종료 코드, 실패/skip 수, 로그를 읽는다. 통과, 실패, 미실행을 구분한다. lint 통과와 제품 동작 성공을 같은 것으로 취급하지 않는다.
5. 이미 통과한 검사를 변경·새 실패·미해결 우려 없이 반복하지 않는다. 실패하면 실제 원인을 분석하고 수정된 범위에 맞게 재검증한다.
6. 에이전트가 수행한 결과도 diff와 증거로 확인한다. 정적 스킬 검증을 모델 행동 평가나 실제 제품 검증으로 확대 해석하지 않는다.
7. 커밋/PR은 승인된 범위에서 준비한다. 관련 파일만 포함하고 검증 결과와 제한을 설명한다.

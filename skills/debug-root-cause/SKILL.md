# 원인 분석

1. 기대 동작과 실제 동작, 재현 입력, 실행 명령·환경·종료 코드를 확보한다.
2. 실제 로그와 스택 트레이스를 읽는다. 첫 관련 오류와 호출 경로를 찾고 마지막 연쇄 오류만 수정하지 않는다.
3. 가능하면 수정 전 최소 재현을 실행한다. 실행할 수 없으면 정적 추정이라고 표시한다.
4. 근거가 있는 가설을 우선순위로 정하고 한 번에 하나의 변수로 확인한다. 무작위 설정 변경과 같은 재시도를 반복하지 않는다.
5. 원인과 실패 조건을 연결한 최소 수정과 회귀 테스트를 만든다. 무관한 리팩터링은 분리한다.
6. 재현 테스트, 관련 테스트, 필요한 빌드/통합 검증을 실행한다. 문제가 남으면 새 관측으로 가설을 수정한다.
7. 기존 실패와 이번 변경으로 발생한 실패, 환경 제약을 분리해 보고한다.

기록 형식은 [진단 기록](references/evidence.md)을 사용한다.
